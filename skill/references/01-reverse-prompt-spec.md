# 08 · 参考图反推 + 动作组 + 文案规格（图片笔记流水线）

> 来源：用户 2026-09-13 逐条口述的硬性规格。**这是输出契约，不是建议**——格式、分布、禁止项都由品牌方定死。
> 一条笔记的流水线：`参考图(O) → 反推环境提示词(P) → 首图(X) → 8 组动作提示词(Y–AF) → 8 组图(F–M) → 小红书文案(C/D/E)`

## 一、模板列位与落位约定（实测上传件）

| 列 | 含义 | 列 | 含义 |
|---|---|---|---|
| A | 序号 | **O** | **参考图**（环境反推来源） |
| B | ip 地区 | **P** | **反推提示词** |
| **C** | **标题** | Q | 人脸图（正/左/右三视图） |
| **D** | **正文** | R–S | 上身效果图 1–2 |
| **E** | **话题** | T–W | 平铺图 1–4 |
| F–N | 图片 1–9 | **X** | **首图** |
| | | Y–AG | 动作提示词 1–9 |
| | | AH | 平台穿搭热门话题 |

**落位（沿用既有约定，勿擅自改）**
- 首图 → **X 列**（每行 1 张）

- 动作提示词 1–8 → **Y–AF**，AG 留空

⚠️ **反推的来源是 O 列「参考图」**（表头即名）。Q 列是「人脸图」三视图，**不含环境，不用于环境反推**——用户口头可能说成「Q 列这张参考图」，**以表头为准**，发现不一致时按 O 列做并说明一句。

## 二、反推输出契约（五段固定格式，不额外解释）

只反推**【环境与拍摄】**，**不反推【人物与服装】**。固定五段：

```
【场景】       空间类型、结构、陈设与道具，以及各自的画面位置
【光影】       光源类型（窗光/店内暖光/阴天散射/直射阳光）、方向、高度、
              软硬、色温、明暗比、投影形态、特殊光斑形态
【镜头与构图】 焦段感、景别、视角高度、主体位置、留白比例、裁切方式
【色调与质感】 主色与辅色、饱和度、对比度、颗粒感、后期倾向
【可复用关键词】8–12 个可直接拼进生图提示词的关键词
```

### 必须剥离（一律不描述）
- **人物**：脸、发型、身材、姿态、表情、肤色。若参考图里有人，**只保留「人物在画面中的位置、朝向、景别占幅」**。
- **服装**：款式、颜色、材质、工艺、品牌、配饰。

### 硬性要求
1. **只描述画面里看得见的东西**；看不到的不补。不虚构参考图中不存在的建筑结构、家具、道具、文字、Logo、装饰纹样。
2. **不确定的部分标注「参考图未提供」**，不要猜。（例：店内货架内容、店招文字）
4. 按上述五段固定格式输出，**不要额外解释**。

### 写法参照（位置要具体到百分比）
> 「浅米白抹灰墙面占满背景上部约 2/3」「木框横向长窗位于横向约 20%–50%、占画面高约 12%」
> 「画面右下角有一个方形金属排水井盖」「人物位于画面中央偏右（横向 55%–70%），全身入画，面朝画面左侧」

## 三、8 组动作提示词：格式与强制分布

**每行一行，固定七段**：

```
【组N】机位｜景别｜动作｜视线｜接触关系｜光影变化｜一句话完整提示词
```

### 强制分布（不达标即返工）
| 维度 | 要求 |
|---|---|
| 机位 | 正面 ≥2 · 3-4 侧 ≥3 · 全侧 ≥2 · 背面 ≥1 |
| 景别 | 全身 ≥4 · 七分 ≥2 · 半身 ≥2 |
| 视线 | 看镜头 ≤2 |
| 覆盖度 | 8 组中机位/景别/动作**各自至少覆盖 3 种不同值** |
| 去重 | **不允许两组以上完全同款** |

### 不变的（必须锁死）
提示词的**空间结构、家具、门窗、地面、色调、搭配全部不变**，只改变：**相机点位、景别、光照角度、人物动作**。
同街区**光锁单一时段**（15:30–17:00）。

### 保留真实拍摄痕迹
轻微运动模糊、轻微噪点、偏轴构图、边缘自然裁切、轻微过曝或欠曝的随手拍感。
背景**允许出现行人与车辆**（真实感优先），但需轻微虚化、不得抢夺主体。

### 动作写法
「正在做某事的一瞬间」、自然真实、不浮夸、有活人感。

> **具体动作从 `10-action-library.md` 的条目库取**（11 族 112 条，带机位/景别/接触/风险标记；
> `X` 族 = 从真实小红书爆款封面**反推**的动作，真实感下限最高，优先用），
> 抽组顺序与配比见该篇 §四，落表前跑 `scripts/check_action_distribution.py` 过闸门。

## 四、逐项锁定的人脸 / 比例 / 禁止项

**人脸必须完全一致，逐项锁定且不得修改**：
脸型 · 五官比例 · 眼型与眼皮 · 鼻型 · 唇形 · 下颌线 · 发际线 · 肤色 · 妆容 · 发色与发长

**强制一致**：8 组的人脸、服装、道具、**光照方向**必须与首图一致。

### ★服装锁定要写到「结构细节」层级（2026-09-13 用户纠正 · 裙子开衩）

只写「款式/颜色/材质一致」不够——模型会**自由发挥结构性细节**。实测被用户打回的一项：

> 行2 组8 的裙摆被模型自行加了一道**开衩**，用户要求「**裙子不开衩**」重跑 → 重跑 1 张（44s）即过。

**锁定清单必须逐项点到（尤其下装与鞋）**：
- **下摆形态**：闭合筒形 / 是否开衩、开叉、前开衩、侧缝开口 ← **最高频自由发挥项**
- **鞋**：同款、同高度、**同跟型（低跟 vs 高跟）** ← **次高频漂移项**（首图低跟、某些组被画成细高跟）
- 领型 / 袖长袖型 / 门襟与纽扣数 / 口袋位置 / 腰线分割 / 缝线褶皱走位

**单张返工的做法**（比整批重跑便宜得多，≈45s/张）：
1. 保留原组提示词不动，把修正项**独立成段**、以「【本次修正·必须遵守】…」开头（强动词：闭合、连续完整、没有任何开衩）
2. 参考图仍取**首图**（不是上一版成品），否则会把上一版的错误一起继承
3. 产物名加 `_修正版` 后缀，组装脚本按 `_修正版` 优先取件

**强制比例**：
- 头身比 **1:7–1:8**
- 参照物：**门高约 2.1 m · 椅面约 0.45 m · 桌高约 0.75 m**
- 不得出现巨人感、矮小感、漂浮感

**禁止道具**：酒杯 · 奢侈品包袋 Logo · 香烟 · 网红道具 · 夸张花艺

## 五、文案规格（据 F–N 内嵌图生成）

| 项 | 规格 | 落位 |
|---|---|---|
| 标题 | **15 字以内**，带 ins 字体或表情包 | **C 列** |
| 话题 | **5 个**，**强制真实存在于平台上、符合平台规则**；符合图片描述的感觉；**含平台当下最热门的一个存在的穿搭话题** | **E 列** |
| 正文 | 符合品牌调性 | **D 列** |

⚠️ **话题不许猜**：必须先检索平台确认该话题真实存在（本库技能 `ricovea-copywriting` 有 opencli 检索命令 / 查看模板 AH 列「平台穿搭热门话题」），再写入。

### 话题验证的具体做法（2026-09-13 实测）

```bash
export https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890
for t in 候选1 候选2 候选3; do echo "── #$t"; \
  ~/.local/bin/opencli xiaohongshu search "$t" -f yaml --limit 3 2>/dev/null \
  | grep -E '^\s+(title|likes):' | head -4; done
```

**判读法**：每个候选搜一遍，看返回笔记的**点赞量级**当活跃度代理——能返回真实笔记 = 话题存在；
取**当季最高热**的那条做「当下最热门话题」。同时验 4–6 个候选，最后只保留 5 个最贴画面调性的。

- 实测参考量级：`#早秋穿搭` 首条 5541 赞（9 月季节性最热）、`#allblack穿搭` 1.5 万、
  `#街拍穿搭` 3435、`#松弛感穿搭` 2581、`#低饱和穿搭` 526
- ⚠️ `opencli xiaohongshu ask`（问小红书点点）**走 UI 自动化、容易失败**（实测报
  `Cannot read properties of undefined`）——**别把它当唯一验证路径**，用 `search` 兜底即可

## 六、执行顺序与门禁

1. 反推 → P 列（五段契约）
2. 首图 → X 列（输入：人脸图 Q + 上身效果 R/S + 平铺 T–W + P 提示词）
3. 动作提示词 → Y–AF（先校验强制分布，再落表）
4. 8 组图 → F–M（**以首图为 edit 参考**保一致，不要 8 次独立文生图）
5. 文案 → C/D/E（话题先检索）
6. **回填** → 用 `scripts/xlsx_surgery.py`（**不可用 openpyxl 直接保存，会丢光参考图** → 见 `07-image-gen-constraints.md` §九）
7. **导出上传件**（客户拿到表还要单独发小红书）：按**发布顺序**导出单图 → `01_首图 → 09_组8`，
   尺寸 **1080×1440**（小红书原生）、JPEG q92；目录 `图片笔记<日期>_上传用/行<N>/`。
   文件名带序号 + 行号，避免多行混在一起上传时错序。

**生图是付费动作 → 拿不准先跑一行（首图+8 组 = 9 张）验证人脸一致性，再批量。**
安全性门禁拦下生图命令时：**不重试、不换路径绕行**，把进度与阻塞点如实报给用户并请其放行。

### 实测基线（v1.1 · 2026-09-13 行2 全流程跑通）

| 项 | 实测值 |
|---|---|
| 单张耗时 | 38–48s；首图 + 8 组 ≈ **5.5 分钟**（后台跑 + `notify_on_complete`） |
| 一致率 | 人脸 / 发型 / 服装 / 光向 **8/8 一致**（漂移仅鞋跟高度、背景车人） |
| 交付件 | 9 图内嵌 F–M + X，P/Y–AF/C/D/E 全填，23.3MB（体积由客户原始参考图主导） |
| 文案实测 | 标题 8 汉字 + ins 字体；正文 154 字 / 14 段 / 每行 ≤12 字；话题 5 个全部检索验证存在 |

**执行前必读**：`07-image-gen-constraints.md` **§十 生图执行与通道排障**（尺寸 16 倍数约束 / 参考图压缩 /
`apikey error` 三层排查 / 成功判定用 glob / 扩展名被追加 / 挂起可续跑）。
