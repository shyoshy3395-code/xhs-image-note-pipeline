## 五、已知坑（改提示词前先读）

1. `xlsx_surgery` 行高解析曾被 `customHeight="1"` 劫持 → 图缩成 15×20px（见 `《xlsx 内嵌坑位》`）
2. 先改行高再算图尺寸 → 图永远按旧行高缩放（同上）
3. 一次调用必须写**全部浮图**（新增 + 模板已有），否则旧浮图变死链
4. vip 不支持并发，必须串行；且两边都要 16 的倍数
5. 生图接口 必须**去代理**；opencli 搜索**要代理**、下载**去代理**
6. 长文本要给单元格加 wrapText，否则 `\n` 不换行

7. **机位只认四大类**（正面 / 3-4侧 / 全侧 / 背面）；`局部特写` 是**景别不是机位**——把它写进配额的机位格，
   该槽位就永远抽不到动作（本次实测：9 组的第 9 组抽成了一整张「全身行走」，特写额度为 0）。
   抽条顺序必须是**先保景别下限**（半身 / 局部特写最容易被漏），再保机位。
8. **8 组与 9 组的配额不同**：8 组版 `3-4侧 ≥3` 且无特写额度；9 组版 `3-4侧 ≥2` + 特写 1。
   改 loader 的 `QUOTA` / `QUOTA_FLOOR` 常量前，先对一遍 `prompts/04-nine-groups.md` 的配额表。
9. **动作要过「空间关」**：【动作提示词库】条目带 `环境(台阶) / 环境(长椅) / 环境(扶手)` 依赖 —— 机位配额达标但空间里
   没有该物，就是拍不出来的动作（本次：临街砖墙转角差点排上「上半步台阶」）。
   用 `--space "墙面,玻璃门,路缘"` 声明本空间可用环境物，loader 会把不匹配的动作**排到队尾（不淘汰，保配额）**。

## 八、已知坑（2026-09-18 新增，均实测踩到）

13. **9 组提示词要写 Y–AG，不是 F–N**：`Y Z AA … AG`（第 25–33 列）才是「动作提示词」列；F–N 是图片列，
    写进去会被浮图盖住、且交付闸门报「组列空」。交付前必跑 `verify_image_note_xlsx.py`（它会逮到）。
14. **文案字数按「不含换行」计**：闸门口径 154–182 字符是**去掉 `\n` 之后**的字数。按含换行算会虚高约 13 字
    （实测 159 → 146 被判 FAIL）→ 自查用 `len("".join(lines))`，别用 `len("\n".join(lines))`。
15. **首图失败必须中止**：首图是九组的一致性锚点，失败还硬跑只会得到另一套人 / 衣。
    `run_image_note.py` 已加守卫（首图缺失 → 打印原因并非零退出，提示可续跑）。
16. **生图接口会偶发瞬时 400**：同提示词同参考图重试即通（实测：同一参数连续 5 次 HTTP 400，单独重试一次 41s 成功）。
    脚本已含「5 次重试 + 20s 退避 + 可续跑（已存在即跳过）」——遇到失败**先原样续跑**，不要改提示词、不要换参考图。
17. **用户说「重新开始」时先归档再跑**：把 `行N_gen/` 整体改名（如 `行N_gen_第1次归档/`）再建空目录重跑，
    既保留上一轮证据便于对比，又不让续跑逻辑误跳过旧图。

    ④ 卡点是**服务端额度或故障**时，先用一条一句话提示词探活，区分「额度问题」与「提示词问题」（§九 22）——
       **额度类卡点绝不改提示词**。

29. **人脸一致性核验（交付规格第一条 · 2026-09-19 固化为固定环节）**：交付规格第一条是「人脸与模板 Q 列人脸图为同一人」，
    但 `qc_contact_sheet.py` 的接触表里**只有成图、没有参考人脸** —— 它只能验「行内是不是同一张脸」，
    **验不了「是不是模板里那个人」**。所以出图后要跑第二张表：
    ```bash
    python3 scripts/qc_face_match.py <工作目录> <交付.xlsx> 2 3 4 5 6 --out ~/Desktop/Hermes
    # → 人脸一致性核验.jpg（上排＝Q 列 DISPIMG 参考人脸原图／下排＝该行生成首图）
    ```
    **抽取原理**（要手搓就照这个走）：`xl/cellimages.xml` 里每个 `<xdr:pic>` 带 `name="ID_XXXX"`，
    同一 pic 内的 `<a:blip r:embed="rIdN"/>` → `xl/_rels/cellimages.xml.rels` 的 `Target="media/imageX.png"`；
    行内 Q 单元格公式是 `=_xlfn.DISPIMG("ID_XXXX",1)`（正则要兼容 `&quot;` 转义）。
    ⚠️ **必须逐 `<xdr:pic>` 块整体匹配**，正则跨 pic 抓 ID 会让 ID 与媒体文件错配。
    判读纪律：① 拼图**放大到短边 ≥420px** 再交视觉模型（缩略图里人脸只有几十像素，必判不准）；
    ② 结论三档 —— 一致 / 基本一致（允许妆容与光线的轻微差异）/ 明显不是同一人；
    ③ 判死 → **该行整行重跑**并归档 `行N_gen_第k次_人脸不符归档/`（首图是九组一致性锚点，见 §八 · 首图失败）。
    2026-09-19 五行批量实测 **5/5「基本一致」通过**：这一步成本极低（纯离线拼图、不调 API），
    却是唯一能证明「出图的人 ＝ 模板要的人」的证据 —— **别用肉眼扫一眼就放行**。

    | 高危动作 | 问题 | 替换为 |

    | `C01 蹲下系鞋带`（3-4侧｜七分） | 蹲姿手部高危（多指/鞋带糊） | `S04 肩背轻靠墙面`（3-4侧｜七分｜✅） |
