## 五、已知坑（改提示词前先读）

1. `xlsx_surgery` 行高解析曾被 `customHeight="1"` 劫持 → 图缩成 15×20px（见 `《xlsx 内嵌坑位》`）
2. 先改行高再算图尺寸 → 图永远按旧行高缩放（同上）
3. 一次调用必须写**全部浮图**（新增 + 模板已有），否则旧浮图变死链
4. vip 不支持并发，必须串行；且两边都要 16 的倍数
5. 生图接口 必须**去代理**；opencli 搜索**要代理**、下载**去代理**
6. 长文本要给单元格加 wrapText，否则 `\n` 不换行

7. **机位只认四大类**（正面 / 3-4侧 / 全侧 / 背面）；`局部特写` 是**景别不是机位**——把它写进配额的机位格，
   该槽位就永远抽不到动作（本次实测：9 组的第 9 组抽成了一整张「全身行走」，特写额度为 0）。
   抽条顺序必须是**先保景别下限**（半身 / 局部特写最容易被漏），再保机位。
8. **8 组与 9 组的配额不同**：8 组版 `3-4侧 ≥3` 且无特写额度；9 组版 `3-4侧 ≥2` + 特写 1。
   改 loader 的 `QUOTA` / `QUOTA_FLOOR` 常量前，先对一遍 `prompts/04-nine-groups.md` 的配额表。
9. **动作要过「空间关」**：【动作提示词库】条目带 `环境(台阶) / 环境(长椅) / 环境(扶手)` 依赖 —— 机位配额达标但空间里
   没有该物，就是拍不出来的动作（本次：临街砖墙转角差点排上「上半步台阶」）。
   用 `--space "墙面,玻璃门,路缘"` 声明本空间可用环境物，loader 会把不匹配的动作**排到队尾（不淘汰，保配额）**。

**R 列与 S 列（上身效果图）只做上身 / 版型参考；实际要生成的服装一律以 T 列与 V 列（平铺图）为准。**

1. **锁词来源** = T 列（上装/主件）＋ V 列（下装/腰带等），可辅以 U / W（同件背面）补细节。
2. **生成参考图必须排除 R/S**：`run_image_note.py` 的 `--cover / --face / --up1 / --up2 / --flat`
   只传「封面（环境）＋ 人脸 ＋ T/V 平铺（＋同件背面）」。
   实测教训：某模板 R/S 是「白衬衫+黑领带+深灰超短裙+黑及膝靴」，T/V 是「白衬衫+黑领带+**深蓝阔腿牛仔+深棕皮腰带**」——
   两套完全不同；R/S 一起喂给模型会**串成 R/S 那套**。
3. **质检专门核对串装**：首图与九组必须与 T/V 一致（裙 / 靴 / 腰带 / 领带的有无最容易串）。

## 八、已知坑（2026-09-18 新增，均实测踩到）

10. **9 组提示词要写 Y–AG，不是 F–N**：`Y Z AA … AG`（第 25–33 列）才是「动作提示词」列；F–N 是图片列，
    写进去会被浮图盖住、且交付闸门报「组列空」。交付前必跑 `verify_image_note_xlsx.py`（它会逮到）。
11. **文案字数按「不含换行」计**：闸门口径 154–182 字符是**去掉 `\n` 之后**的字数。按含换行算会虚高约 13 字
    （实测 159 → 146 被判 FAIL）→ 自查用 `len("".join(lines))`，别用 `len("\n".join(lines))`。
12. **首图失败必须中止**：首图是九组的一致性锚点，失败还硬跑只会得到另一套人 / 衣。
    `run_image_note.py` 已加守卫（首图缺失 → 打印原因并非零退出，提示可续跑）。
13. **生图接口会偶发瞬时 400**：同提示词同参考图重试即通（实测：同一参数连续 5 次 HTTP 400，单独重试一次 41s 成功）。
    脚本已含「5 次重试 + 20s 退避 + 可续跑（已存在即跳过）」——遇到失败**先原样续跑**，不要改提示词、不要换参考图。
14. **用户说「重新开始」时先归档再跑**：把 `行N_gen/` 整体改名（如 `行N_gen_第1次归档/`）再建空目录重跑，
    既保留上一轮证据便于对比，又不让续跑逻辑误跳过旧图。
